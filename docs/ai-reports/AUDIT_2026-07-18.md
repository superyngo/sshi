# Codebase Audit — sshi v1.6.1

**Date:** 2026-07-18
**Branch:** `main` (clean, in sync with `origin/main`)
**Methodology:** Three parallel sub-agents audited (1) TUI vs UI Design Principles, (2) code quality & architecture, (3) performance & concurrency. Every finding carries file:line evidence. `cargo clippy --all-targets` and `cargo clippy --all-targets --features tui` both pass clean.
**Totals:** 116 findings — 23 HIGH, 51 MED, 42 LOW.

The companion implementation plan is `docs/plans/2026-07-18-audit-fixes.md`.

---

## Executive summary

sshi is a well-structured mid-stage Rust codebase. The headless-core separation is real for `check`/`run`/`exec`/`cp`/`list`/`log`, the layering is clean (no leaky upward deps), clippy is clean, and SQL is fully parameterized. Four systemic issues cut across all three audits:

1. **AGENTS.md is materially stale** — documents the pre-russh world ("NEVER use embedded SSH libraries"), mandates `thiserror` (not in `Cargo.toml`), claims sync uses BLAKE3 (actually SHA-256), and references a `sshi-tui` binary that doesn't exist.
2. **The `_core` discipline is incomplete** — `init` and `checkout` have no `*_core` variant; they call `printer::*`/`println!` directly from 400–600 line `run()` functions. The TUI cannot drive them without violating AGENTS.md §7.3.
3. **Database access is sync on the tokio executor** — zero `spawn_blocking` calls; under the TUI's per-op current-thread runtime, every DB write freezes every concurrent SSH task. Missing `busy_timeout` + `synchronous=NORMAL` PRAGMAs compound this.
4. **`sync_inner` is a 678-line function** with O(F²·H) scans, unbatched DB writes, and 7 interleaved phases. It is the largest complexity + perf hotspot.

## 1. UI / UX audit (TUI vs design principles)

**Scope:** `src/tui/**`, checked against the 23 UI Design Principles. **36 findings (8 HIGH, 16 MED, 12 LOW).**

### A. Architecture

**P1 — Single source of truth — PARTIAL**
- **[HIGH]** State-mapping bug: `OperateState::new` initialises the **shared** `dry_run` field from `persisted.sync_dry_run` (`app_state.rs:152`). The shared dry-run flag (read by `trigger_execute` at `app.rs:292`) round-trips through the sync-specific field, and `save_state` (`app.rs:638`) writes only `sync_dry_run` from `self.operate.sync_dry_run`, so the user-visible shared dry-run is not persisted at all.
- **[MED]** `shell_label(ShellMode)` is implemented three times with identical bodies — `components/target_filter.rs:312`, `tabs/operate_tab.rs:190`, `tabs/view_tab.rs:240`.
- **[MED]** Group-collection logic forked three ways: `App::available_groups` `app.rs:347-359`, `collect_groups` `target_filter.rs:338-345`, `collect_known_groups` `tabs/config_tab.rs:2767-2779`.
- **[MED]** `ShellMode` (`state/persist.rs:99`) duplicates `ShellType` (`config/schema`); two parallel enums plus hand-written `to_shell_type`/`from_shell_type` mappings `persist.rs:107-123`.
- **[LOW]** `focus_style`/`view_focus_style`/`radio_style` reimplemented per tab with the same reverse-video-or-bold logic — `operate_tab.rs:176`, `view_tab.rs:180`, `target_filter.rs:328`, `member_picker.rs:246-252`.
- **[LOW]** `chips`/`view_chips`/`format_chips` duplicated — `operate_tab.rs:577`, `view_tab.rs:274`, `target_filter.rs:320`.

**P2 — Cross-platform adaptation — PASS.** One TUI binary over shared `commands::*_core`; signal handling split with `#[cfg(unix)]`/`#[cfg(windows)]` (`app.rs:4231-4278`); external editor via `$VISUAL`/`$EDITOR`/platform defaults (`app.rs:3597-3605`); `TerminalGuard` RAII uniform (`terminal.rs:14-29`).

**P3 — Native surfaces preferred — PASS.** External editor for long-form config edits; crossterm primitives used directly; no reinvented raw-mode/alt-screen.

**P4 — Shared interface for identical operations — PARTIAL.**
- **[MED]** Three near-identical multi-select pickers (`MemberPicker`, in-form `GroupPickerState`, `DirectGroupPickerState`) each implement their own cursor/scroll/toggle logic.
- **[LOW]** The `Focusable` trait (`focus.rs:138-160`) exists but is exercised only by adapter tests; production dispatch reimplements the logic per tab. Either delete `Focusable` or route one canonical list through it.

### B. Focus, selection, feedback

**P5 — Focus cursor always visible — PASS.** Reverse-video strong cursor + bold-only weaker "focused but panel not active" tier (`operate_tab.rs:177-184`, `view_tab.rs:180-184`, `input_field.rs:132-138`). Errors via status line, not row dimming (`app.rs:4037-4040`).
- **[LOW]** When NavBar holds focus, intra-panel row cursor falls back to bold-only — visually identical to non-focused bold labels. Consider a third tier (accent colour, no reverse, no bold).

**P6 — Committed + preview two-set selection — FAIL.**
- **[MED]** `MemberPicker::toggle` writes directly to the committed `Vec<bool>` (`member_picker.rs:160-174`); same for `GroupPickerState` (`config_tab.rs:1321-1327`) and `DirectGroupPickerState` (`config_tab.rs:2401-2407`). No preview overlay, no range-select. Cancel-on-Esc works by accident (picker dropped); any future parent mutation from inside the picker breaks the rollback property.

**P7 — Sticky-cursor scrolling — PASS.** `Viewport { selected, scroll_y, visible_height, item_count }` with maintained invariant `scroll_y <= selected < scroll_y + visible_height` (`viewport.rs:6-48`).

**P8 — Confirm destructive + preserve state across redraws — PARTIAL.**
- **[MED]** Restoration is **positional**, not by identity — `restore_selection` clamps `snap.sidebar_idx` against new `items.len()` (`config_tab.rs:357`). Delete host #2 of 5 and the cursor lands on whatever is now at position 2, not on the next host by id.
- **[LOW]** Reload-from-external-editor (`App::do_open_editor` `app.rs:3634-3648`) does NOT call `capture_selection`/`restore_selection`. The comment at `config_tab.rs:449-467` defends the save path, but the editor path bypasses it.

**P9 — Failure never destroys WIP — PARTIAL.**
- **[MED]** `OperationError` and `OperationCancelled` overwrite any prior `self.error` string (`app.rs:803-810`). Previous diagnostic messages are silently lost.
- **[LOW]** Sync ad-hoc path push is fire-and-forget on Enter (`app.rs:2095-2097`); the only "undo" is Del which pops the last entry (`app.rs:2900`). No undo for accidental Enter.

- **[MED]** Cursor moves by Rust `char` (codepoint), not grapheme (`input_field.rs:178-183`). Emoji ZWJ sequences or combining marks can be split.

**P13 — Del clears clearable inputs — PASS.** `app.rs:2860-2905` clears optional fields; `config_tab.rs:721-740` clears optional scalars and refuses with banner for required `name`.

**P14 — Global keys + footer — PARTIAL.** Persistent per-tab key-hint footer (`app.rs:4042-4057`); Esc peels one layer (`app.rs:2486-2563`).
- **[MED]** Esc on Config is 2-way toggle; Operate/View are 3-way. Documented inconsistency (`app_state.rs:13-15`).
- **[LOW]** `Ctrl+C` is hard-quit even mid-op. Footer shows `q:Quit` but not `Ctrl+C`.

## 3. Performance & concurrency audit

**Scope:** entire `src/`. **33 findings (9 HIGH, 14 MED, 10 LOW).**

### Critical paths analyzed

- **Sync (3-stage).** Stage 1 parallel + well-bounded. Stage 2 per-file O(H). Stage 3 local-tempdir relay (correct design). Issues: unbatched DB writes on executor thread; `Vec::contains` scans are quadratic in F × H × P.
- **Session pool.** Concurrent connect with semaphore. `home_dirs` cached behind correctly-scoped `tokio::sync::Mutex`. Issues: SFTP subsystem re-opened per op; no SSH keepalive.
- **Metrics collection.** Batches all metrics into 2 SSH calls per host — well-designed. DB fan-out sequential and blocking.
- **TUI.** Main loop drains events non-blockingly, redraws only when dirty. Every `execute_*` spawns dedicated OS thread + fresh current-thread runtime (workaround for `&Context: !Send`).

### 1. Async correctness

- **[HIGH]** Blocking `rusqlite` calls inside async fns, no `spawn_blocking` anywhere. Sites: `check.rs:75,79,179,184,190,206,225,229,238`; `sync/mod.rs:559,570,898,909`; `run.rs:113,141`; `exec.rs:140,162`; `cp.rs:151`; `checkout.rs:161,173,255,267`; `log.rs:65`. Under TUI's per-op current-thread runtime, every DB write freezes every concurrent SSH task.
- **[HIGH]** `rpassword::prompt_password` (blocking stdin read) inside async `authenticate` (`auth.rs:77,91`). Under TUI, terminal is in raw mode + no stdin attached; `auth_bridge_tx` captured but never sent to. Passphrase/password auth non-functional in TUI, blocks runtime indefinitely.
- **[MED]** No SSH keepalive — `inactivity_timeout: None` (`session_pool.rs:384,464`). Proxy keep_alive only holds the Handle, doesn't send packets. Aggressive `ClientAliveInterval` can silently disconnect mid-stage.
- **[LOW]** `tokio::spawn` for proxy keepalive tracked via cancel oneshot — correct.
- **[LOW]** No `futures::join_all` — codebase uses `Vec<JoinHandle>` + sequential `await` (preserves concurrency). Confirmed not-an-issue.
- **[LOW]** No recursive async. Confirmed not-an-issue.

### 2. Concurrency bottlenecks

- **[HIGH]** Head-of-line blocking in `ConcurrencyLimiter::acquire` (`concurrency.rs:32-43`). Acquires **global permit first, then per-host permit**. N tasks queued on host A's semaphore while holding global permits will starve host B. Fix: acquire per-host first then global, or drop global sem.
- **[MED]** Dual semaphores in two sync paths — `sync/mod.rs:340-354` and `distribute.rs:30-54` create fresh `Semaphore::new(ctx.concurrency())` while `pool.limiter` already exists.
- **[MED]** `for handle in handles { handle.await? }` serializes result collection order; if host[0] is slowest, later results buffer. Use `JoinSet::join_next()` (already used in `session_pool.rs:288`). 9 sites.
- **[LOW]** `sem.acquire().await.unwrap()` panics if semaphore closed — 11 sites. Defensive only.
- **[LOW]** Sequential decision loop in sync (`mod.rs:515`).

### 3. Memory & allocations

- **[HIGH]** `HostEntry` deep-cloned per spawned task — `cp.rs:91`, `run.rs:64`, `exec.rs:105`, `check.rs:112`, `sync/mod.rs:344`, `sync/collect.rs:112,218`, `distribute.rs:40,98`. ~5 heap allocs per clone × every host × every command. Fix: `Arc<HostEntry>`.
- **[MED]** `paths.to_vec()` per host in batch collect (`collect.rs:219`). For F=1000 × H=500 = 500K string clones per stage. Use `Arc<[String]>`.
- **[MED]** `AppConfig` fully cloned per TUI op — `app.rs:1169,1271,1362,1463,1540`. Multiple MB per click for 500-host config. Use `Arc<AppConfig>`.
- **[MED]** Whole-file buffering for SFTP transfer (`sftp.rs:85,129`). 64 MB cap. Many concurrent transfers each hold up to 64 MB.
- **[MED]** `stdout: Vec<u8>` realloc on every `ChannelMsg::Data` chunk (`session_pool.rs:516-533`).
- **[LOW]** `expanded_files`/`new_paths` cloned in path-expansion loop (`sync/mod.rs:301-326,367-394`).
- **[LOW]** `String::from_utf8_lossy(&stdout).to_string()` always copies (`session_pool.rs:539,540`).
- **[LOW]** TUI event channel unbounded (`app.rs:137`). `BoundedEventSender` in `async_bridge.rs:104` is dead code.

### 4. SSH-specific (russh)

- **[HIGH]** SFTP subsystem channel re-opened on every op — `sftp.rs:46` called from `sftp.rs:84,116,183`. For `cp` of 100-file directory = 100 SFTP negotiations per host. Cache `SftpSession` per host.
- **[MED]** SFTP probe runs unconditionally per sync invocation (`sync/mod.rs:181`). Cache results in state DB; skip when `--dry-run`.
- **[MED]** `cp` uploads files one at a time per host (`cp.rs:105-110`). Sequential per host.
- **[LOW]** DNS resolution not cached (`session_pool.rs:395`). Acceptable for one-shot.
- **[LOW]** No connection reuse across commands — TUI sessions could keep warm pools.
- **[LOW]** Per-op timeout is single value applied to every stage.

### 5. SQLite concerns

- **[HIGH]** Missing `PRAGMA busy_timeout` (`db.rs:48` only sets `journal_mode=WAL`). Concurrent CLI + TUI access fails immediately with `SQLITE_BUSY`.
- **[HIGH]** Missing `PRAGMA synchronous` (defaults to FULL). Combined with WAL, `synchronous=NORMAL` is documented fast/safe combo, ~5–20× faster for small writes.
- **[MED]** N+1 INSERTs around sync fan-out (`sync/mod.rs:558-568,898-907`). 500-host sync of one file = 500 separate auto-committed INSERTs.
- **[MED]** No transactions around batched writes. Each `execute` is its own transaction → its own fsync under default `synchronous=FULL`.
- **[MED]** No prepared-statement caching. `prepare_cached` not used anywhere.
- **[LOW]** `Connection::open` per command/op. TUI opens fresh connection per op.
- **[LOW]** Migration uses `pragma_table_info` defensively. OK.

### 6. TUI perf

- **[MED]** 50 ms fixed poll interval (`app.rs:77`, used at `:713`). Loop wakes 20×/sec even idle. Use `crossterm::event::EventStream` + `tokio::select!`. ~5% CPU baseline on laptops.
- **[MED]** Per-op OS thread + current-thread runtime (`app.rs:1183` + 4 sites). ~150 µs per op + DB re-open.
- **[MED]** Full `AppConfig` clone per op (see §3).
- **[LOW]** Redraw strategy correct (`app.rs:706-709` dirty-gated). ✓
- **[LOW]** No background polling timers. ✓
- **[LOW]** Auth bridge forwarder detached (`app.rs:679-683`) — correct.

### 7. Algorithmic complexity

- **[HIGH]** `scope_collect_result` is O(F · H · P) (`collect.rs:75-98`). `paths.contains(path)` inside per-file filter loop. Use `HashSet<String>` values or inverted `path → Vec<host>` index.
- **[HIGH]** `new_paths.contains(file_path)` is O(F²) (`sync/mod.rs:305,372`). For E=10k files = 10⁸ comparisons. Maintain `HashSet<String>` seen-set.
- **[MED]** `union_dir_expansions` O(files²) (`collect.rs:268-285`).
- **[MED]** `!targets.contains(h)` linear (`decide.rs:38,134`).
- **[LOW]** `resolve_hosts` filters O(H·N) (`commands/mod.rs:127-144`).
- **[LOW]** `select_named` O(W·E) (`commands/mod.rs:230-268`).
- **[LOW]** `filter_reachable`/`filter_sftp_capable` rebuild fresh HashSet every call (`pool.rs:101-102,117-118`).

### 8. Subprocess / IO efficiency

- **[HIGH]** Local tempdir relay downloads source file fully to disk before re-upload (`distribute.rs:24-28,81-82`). For 1 GB × 5 decisions = 5 GB disk write+read. Pin to tmpfs or chunk-stream through bounded pipe.
- **[MED]** `std::fs::metadata`, `read_dir`, `read_to_string` in async fns (`cp.rs:260,328,349`; `session_pool.rs:48`). Use `tokio::fs::*`.
- **[LOW]** `walk_files` reads whole tree up front (`cp.rs:345-362`).
- **[LOW]** sftp chunk size not tuned.

### 9. Build & startup

- **[HIGH]** No `[profile.release]` overrides in `Cargo.toml`. Defaults: `opt-level=3`, `lto=false`, `codegen-units=16`, `panic=unwind`, `strip=false`.
  ```toml
  [profile.release]
  lto = "thin"          # ~5–15% runtime speedup, +20% link time
  codegen-units = 1     # better inlining
  strip = "symbols"     # ~50% binary size reduction
  ```
  Avoid `panic = "abort"` — codebase relies on JoinHandle catching task panics.
- **[LOW]** Cold-start reasonable. ✓
- **[LOW]** Many small deps could be `optional = true` if binary size matters.
